## 2. 기존 사이트 분석

### 현재 기술 스택
- CMS: XpressEngine (XE) - 2015년경 구축 추정
- 반응형: 미지원 (viewport 1024px 고정)
- SSL: 자체 서명 인증서 (보안 경고 발생)
- jQuery 기반, 레거시 IE 호환 코드 포함

### 현재 메뉴 구조
```
홈
├── 교회 소개
│   ├── 인사말/비전

│   ├── 교회 소개 영상
```

### 기존 사이트 문제점
- 반응형 미지원 (모바일 접근성 없음)
- SSL 인증서 만료/자체 서명 (보안 경고)
- 10년 이상 된 프레임워크 (XE)
- IE 호환 코드로 인한 불필요한 복잡성
- 느린 로딩 속도
- 구시대적 디자인

## 3. 리뉴얼 목표

### 핵심 목표
1. **모바일 퍼스트 반응형** - 전 연령대가 스마트폰으로 쉽게 접근
2. **간결한 메뉴 구조** - 기존 4뎁스 → 최대 2뎁스로 단순화
3. **빠른 로딩** - 정적 생성(SSG)으로 즉각 로딩
4. **쉬운 접근성** - 큰 텍스트, 명확한 버튼, 단순한 네비게이션
5. **유지보수 용이** - 콘텐츠 수정이 쉬운 구조

### 비기능 요구사항
- 다크모드: 미지원 (불필요)
- 다국어: 미지원 (한국어만)
- 로그인/회원가입: 제외 (불필요, 관리자는 Sanity 로그인)
- SEO: 기본 메타태그 + 시맨틱 HTML
- 관리자 화면: **PC 전용** (모바일 관리 지원하지 않음)
- 도메인 이전: MVP 완성 후 별도 진행 (현재 보류)

### 아키텍처 원칙

개발자가 AI 도움을 받아 직접 유지보수하므로, 아래 원칙을 지킨다.

1. **명확한 디렉토리 구조**: 파일 위치만 보고 역할을 알 수 있어야 함
2. **타입 안전성**: 모든 Sanity 스키마에 대응하는 TypeScript 타입 정의
3. **컴포넌트 단일 책임**: 하나의 컴포넌트는 하나의 역할만 수행
4. **블록 시스템 확장성**: 새로운 블록 타입을 추가할 때 스키마 1개 + 컴포넌트 1개만 만들면 됨
5. **테마 변경 용이**: CSS 변수 기반으로 컬러/폰트를 한 곳에서 관리
6. **GROQ 쿼리 분리**: Sanity 쿼리를 별도 파일로 관리하여 데이터 계층과 UI 분리

### 6.2 편집 방식: Visual Editing (실시간 화면 편집)

관리자가 **실제 웹사이트 화면을 보면서** 수정할 수 있는 방식으로 구축한다.

```
┌─────────────────────────────────────────────────────┐
│  Sanity Studio (/studio)                            │
│  ┌────────────────────────────────────────────────┐ │
│  │  실제 웹사이트 미리보기 (iframe)                   │ │
│  │                                                │ │
│  │   ┌──────────────────────────┐                 │ │
│  │   │  남문교회에 오신 것을     │ ← 클릭하면      │ │
│  │   │  환영합니다              │   편집 패널 열림  │ │
│  │   └──────────────────────────┘                 │ │
│  │                                                │ │
│  │   [예배안내 블록]  [설교 블록]  [공지 블록]       │ │
│  │        ↕ 드래그로 순서 변경 가능                  │ │
│  └────────────────────────────────────────────────┘ │
│                                                     │
│  ┌─ 편집 패널 ────────────────────────────────────┐ │
│  │  환영 문구: [남문교회에 오신 것을 환영합니다    ] │ │
│  │  배경 이미지: [📎 이미지 변경]                   │ │
│  │  버튼 텍스트: [예배 안내 보기                   ] │ │
│  │  버튼 링크:   [/about/worship               ▼] │ │
│  └────────────────────────────────────────────────┘ │
└─────────────────────────────────────────────────────┘
```

**구현 기술:**
- `@sanity/presentation`: Studio 내에서 실제 사이트를 iframe으로 띄우고 클릭-편집 연동
- `@sanity/visual-editing`: Next.js 컴포넌트에 편집 가능 영역 표시 (파란색 테두리 오버레이)
- Next.js Draft Mode: 발행 전 변경사항을 실시간 미리보기

**관리자 사용 흐름:**
1. `nammoon.or.kr/studio` 접속 → Google 계정으로 로그인
2. Presentation 탭 클릭 → 실제 웹사이트가 화면에 표시됨
3. 수정하고 싶은 텍스트/이미지를 **클릭** → 우측에 편집 패널 열림
4. 내용 수정 → 화면에 **실시간 반영** (저장 전 미리보기)
5. **발행** 버튼 클릭 → 실제 사이트에 반영

### 6.3 블록(모듈) 조립 방식

페이지를 빈 에디터가 아닌, **미리 디자인된 블록을 조립**하여 구성한다.

#### 제공 블록 목록

| 블록 이름 | 용도 | 편집 가능 필드 |
|-----------|------|---------------|
| 히어로 블록 | 대표 이미지 + 환영 문구 | 배경이미지, 제목, 부제, 버튼텍스트, 버튼링크 |
| 예배안내 블록 | 예배 시간표 카드 | 예배명, 시간, 아이콘 (각 예배별) |
| 최신설교 블록 | YouTube 영상 1개 + 설교 정보 | 자동 (최신 설교 데이터 연동) |
| 공지사항 블록 | 최신 공지 2-3개 미리보기 | 자동 (최신 공지 데이터 연동) |
| 오시는길 블록 | 지도 + 주소/교통편 | 주소, 전화번호, 교통편 텍스트 |
| YouTube 영상 블록 | 유튜브 영상 임베드 | YouTube URL만 입력 → 자동 임베드 |
| 텍스트 블록 | 자유 텍스트 영역 | 리치 텍스트 (굵게, 링크 등) |
| 이미지 갤러리 블록 | 사진 여러 장 그리드 | 이미지 드래그앤드롭 다중 업로드 |
| 사역자 소개 블록 | 사역자 카드 그리드 | 사진, 이름, 직분, 소개 |
| 타임라인 블록 | 연혁 표시 | 연도, 내용 (항목 추가/삭제) |

#### 블록 조작 방식

```
메인 페이지 섹션 구성:
  ┌─────────────────────┐
  │ ☰ 히어로 블록       │ ← 드래그 핸들로 순서 변경
  │ ☰ 예배안내 블록     │
  │ ☰ 최신설교 블록     │ ← [✕] 삭제 가능
  │ ☰ 공지사항 블록     │
  │ ☰ 오시는길 블록     │
  ├─────────────────────┤
  │ [+ 블록 추가]       │ ← 클릭 시 블록 목록 표시
  └─────────────────────┘
```

- **추가**: [+ 블록 추가] 버튼 → 블록 종류 선택 → 페이지에 추가
- **삭제**: 블록 우측 [✕] 버튼 클릭
- **순서 변경**: 드래그 앤 드롭으로 위/아래 이동
- **편집**: 블록 클릭 → 편집 패널에서 내용 수정

### 6.4 콘텐츠별 관리 기능

#### 공지사항
- 제목, 본문(리치텍스트), 카테고리(공지/행사), 첨부파일
- 목록에서 바로 수정/삭제
- 발행일 예약 가능

#### 주보
- 이미지 또는 PDF 파일 드래그앤드롭 업로드
- 날짜 선택 → 자동으로 "이번 주 주보"로 표시
- 이전 주보 아카이브 자동 관리

#### 설교 영상
- **YouTube URL만 입력** → 썸네일, 제목 자동 추출
- 카테고리 선택 (주일오전/수요/새벽/특별/3분메시지)
- 설교자, 본문(성경구절), 날짜 입력
- 필수값 미입력 시 저장 차단 (YouTube URL, 제목, 날짜)

#### 교회앨범
- **여러 장 동시 드래그앤드롭 업로드**
- 앨범명, 날짜 입력
- 이미지 순서 드래그로 변경
- Sanity Image CDN이 자동 리사이즈/최적화

#### 기도편지
- 제목, 본문(리치텍스트), 선교사/선교지 정보
- 이미지 첨부 가능

#### 부서 소개 / 예배시간 / 인사말 등 고정 콘텐츠
- Visual Editing으로 **화면에서 해당 텍스트를 클릭하여 직접 수정**
- 사역자 사진/이름/직분 → 카드를 클릭하여 수정
- 예배 시간 → 시간표 항목을 클릭하여 수정
- 버튼의 연결 링크도 클릭하여 변경

### 6.5 실시간 미리보기 & 발행 워크플로우

```
[수정] → [실시간 미리보기 (Draft)] → [발행 (Publish)]
              ↓                          ↓
     관리자만 보이는 상태           실제 사이트에 반영
     PC/모바일 화면 전환 가능
```

- 수정 즉시 미리보기 화면에 반영 (저장 불필요)
- **발행 전까지 실제 사이트에는 영향 없음** (안전)
- Studio 내에서 PC ↔ 모바일 미리보기 전환 가능
- 필수값 누락 시 발행 버튼 비활성화 + 누락 필드 하이라이트

### 6.6 유효성 검증 규칙

## 7. 기술 스택

### 추천 스택

| 카테고리 | 기술 | 선정 이유 |
|----------|------|-----------|
| 프레임워크 | **Next.js 15 (App Router)** | SSG로 빠른 로딩, 검색엔진 최적화, 이미지 최적화 내장 |
| 언어 | **TypeScript** | 타입 안전성, 유지보수성 |
| 스타일 | **Tailwind CSS** | 빠른 개발, 반응형 유틸리티, 일관된 디자인 |
| 배포 | **Vercel** | Next.js 최적 배포 환경, 무료 티어 충분 |
| CMS | **Sanity** | 헤드리스 CMS, Visual Editing으로 화면 보며 직접 수정 가능 |
| Visual Editing | **@sanity/presentation + @sanity/visual-editing** | 실제 사이트 화면에서 클릭-편집 연동 |
| 이미지 저장 | **Sanity Image CDN** | 자동 리사이즈, 최적화, CDN 제공 |
| 지도 | **카카오맵 API** | 국내 서비스에 적합 |
| 영상 | **YouTube 임베드** | 기존 유튜브 채널 활용, 서버 부담 없음 |
| 아이콘 | **Lucide React** | 경량, 일관된 아이콘셋 |

### 왜 이 스택인가?

**Sanity CMS를 사용하는 이유:**
- **Visual Editing (Presentation)**: 실제 사이트 화면을 보면서 클릭으로 수정 (구글 사이트 도구와 유사한 경험)
- **블록 조립 방식**: 미리 디자인된 섹션 블록을 드래그앤드롭으로 추가/삭제/순서 변경
- 무료 티어: API 100K 요청/월, 500MB 스토리지, 사용자 3명 (교회에 충분)
- 이미지 CDN 내장 (자동 리사이즈, WebP 변환, 최적화)
- Next.js와 공식 연동 라이브러리 제공 (`next-sanity`, `@sanity/presentation`)
- Draft → Publish 워크플로우로 안전한 발행 관리

**Next.js를 선택한 이유:**
- React 생태계의 표준 프레임워크
- SSG(정적 생성) + ISR(증분 정적 재생성) 지원 → Sanity에서 저장 시 자동 반영
- 이미지 최적화 (`next/image`) 내장
- Vercel 무료 배포와 완벽 호환

### Sanity 무료 티어 상세

| 항목 | 무료 제공량 | 교회 예상 사용량 |
|------|-----------|----------------|
| API 요청 | 100K/월 | ~10K/월 (충분) |
| 스토리지 | 500MB | 이미지 중심이면 1-2년 사용 가능 |
| 사용자 | 3명 | 목사님 + 사무장 + 개발자 |
| 이미지 CDN | 무제한 변환 | 충분 |

> **이미지 용량 전략**: 500MB로 시작하되, 업로드 시 자동 리사이즈(최대 1920px)로 용량을 절약한다.
> 부족해지면 Cloudinary(무료 25GB, Sanity 공식 플러그인 지원)로 전환한다.

### Visual Editing 참고사항

Sanity Visual Editing은 구글 사이트 도구와 **동일하지 않다**.
- 화면에서 요소를 **클릭하면 우측 편집 패널이 열리는 방식** (화면에서 직접 타이핑하는 방식 아님)
- 정해진 블록 구조 안에서만 수정 가능 (자유 배치 불가)
- 장점: 실제 사이트를 보면서 수정하므로 결과물 예측이 쉬움

## 7. 디자인 가이드라인

### 컬러 팔레트 (CSS 변수 기반 - 언제든 변경 가능)

모든 컬러를 **CSS 커스텀 프로퍼티(변수)** 로 관리하여 한 곳만 수정하면 전체 사이트에 즉시 반영되도록 한다.

| 용도 | CSS 변수명 | 기본값 | 코드 |
|------|-----------|--------|------|
| Primary | `--color-primary` | 네이비 블루 | `#1E3A5F` |
| Primary Light | `--color-primary-light` | 라이트 블루 | `#4A90D9` |
| Accent | `--color-accent` | 골드 | `#C8A951` |
| Background | `--color-bg` | 화이트 | `#FFFFFF` |
| Surface | `--color-surface` | 라이트 그레이 | `#F8F9FA` |
| Text Primary | `--color-text` | 다크 그레이 | `#1A1A1A` |
| Text Secondary | `--color-text-secondary` | 미디엄 그레이 | `#6B7280` |

**컬러 변경 방법**: `tailwind.config.ts`의 theme.colors 또는 `globals.css`의 `:root` 변수만 수정하면 전체 반영.
향후 Sanity Studio에서 관리자가 직접 컬러를 변경하는 "사이트 설정" 기능 확장도 가능.

> 교회의 신뢰감과 품격을 나타내는 네이비 + 골드 조합 (기본값)

### 타이포그래피
- 본문: Pretendard (가독성 우수한 한글 웹폰트)
- 크기: 본문 16px 이상 (노년층 가독성 고려)
- 행간: 1.7 이상

### 접근성
- 최소 터치 영역: 44px × 44px
- 충분한 색상 대비 (WCAG AA 기준)
- 명확한 포커스 표시
- 시맨틱 HTML 구조
